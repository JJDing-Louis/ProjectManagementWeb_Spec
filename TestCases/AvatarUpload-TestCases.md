## 功能案例

### TC-F-AVATAR-001 已驗證 Viewer 上傳 PNG

- 對應需求：§1-1、§1-2、§1-3、§1-4；優先級：P0。
- 前置條件：一位 Email 已驗證的 `Viewer` 登入，原圖為短邊至少 1080 像素的 PNG，本人目前沒有圖片。
- 步驟：在個人設定選圖，調整方形剪裁與位置，確認方形預覽後產生 1080 × 1080 圖片並上傳；讀取本人圖片及資料庫欄位。
- 預期：`PUT /users/me/avatar` 成功；`GET /users/{本人Id}/avatar` 回 200 `image/png`、1080 × 1080；`Accounts.AvatarImage` 非空，沒有額外原圖或檔案；稽核只記錄操作，不記錄圖片內容。
- 後置狀態：本人有一張目前圖片；其他帳號資料不變。
- 自動化對應：`UserApiTests.已驗證Viewer可上傳覆寫本人圖片且他人不可讀寫`、`AvatarImageProcessorTests.已剪裁圖片應重新編碼為1080正方形`。

### TC-F-AVATAR-002 JPEG 上傳與覆寫

- 對應需求：§1-3、§1-4；優先級：P1。
- 前置條件：本人已有 PNG 圖片且 Email 已驗證。
- 步驟：上傳剪裁後的 `.jpg` 或 `.jpeg`；重新整理頁面、重新登入，再讀取圖片與 `Accounts.AvatarImage`。
- 預期：回 200 `image/jpeg`、1080 × 1080；顯示新圖，不再回傳舊圖；資料庫只存目前圖片，重新登入仍可讀取。
- 後置狀態：原欄位被新圖覆寫；無應用程式層級舊版。
- 自動化對應：`UserApiTests.已驗證Viewer可上傳覆寫本人圖片且他人不可讀寫`、`AvatarImageProcessorTests.已剪裁圖片應重新編碼為1080正方形`。

### TC-F-AVATAR-003 三處顯示與無圖備援

- 對應需求：§1-5；優先級：P1。
- 前置條件：有圖與無圖帳號各一，可登入並檢視本人的設定與詳情。
- 步驟：檢查個人設定、桌面側邊導覽、手機導覽與使用者詳情；更新圖片後再檢查；切換無圖帳號。
- 預期：有圖時各處顯示目前圖片並在更新後刷新；無圖時顯示姓名首字；使用者清單不逐筆載入圖片。
- 後置狀態：無資料變更。
- 自動化對應：`userAvatar.spec.ts`、`settingsView.spec.ts`；桌面／手機實際瀏覽器檢查另記錄。

## 邊界案例

### TC-E-AVATAR-004 裁切尺寸與縮放邊界

- 對應需求：§1-3；優先級：P1。
- 前置條件：準備 1079 × 1080、1080 × 1080、1600 × 1200、2160 × 2160 原圖。
- 步驟：依序選圖；對超過 1080 或非方形圖片調整水平、垂直與縮放；確認輸出與 API 回應。
- 預期：短邊 1079 拒絕；1080 × 1080 可原尺寸確認；其他圖片可剪裁為 1080 × 1080，不能放大低於原生 1080 像素的裁切區域；直接送出非 1080 × 1080 圖片時後端回 400。
- 後置狀態：只有確認上傳且 API 成功時圖片更新。
- 自動化對應：`AvatarImageProcessorTests.非1080正方形應要求先剪裁`、`avatarCrop.spec.ts`；檔案選擇 UI 需手動檢查。

## 錯誤與安全案例

### TC-ERR-AVATAR-005 未登入或 Email 未驗證拒絕上傳

- 對應需求：§1-1；優先級：P0。
- 前置條件：未登入請求，以及可登入但 Email 未驗證的 `Viewer`。
- 步驟：呼叫上傳 API，檢查未驗證者畫面與 `Accounts.AvatarImage`。
- 預期：未登入回 401；未驗證回 403 `email_not_verified` 且畫面提示先驗證；欄位不變。既有名稱／電話更新仍可用。
- 後置狀態：圖片不變。
- 自動化對應：`UserApiTests.未登入及未驗證帳號不可上傳大頭貼`、`settingsView.spec.ts.信箱未驗證時沒有大頭貼上傳入口`。

### TC-ERR-AVATAR-006 不得修改或越權讀取他人圖片

- 對應需求：§1-2；優先級：P0。
- 前置條件：兩位一般使用者與一位具 `accounts.read` 的管理者。
- 步驟：一般使用者嘗試以他人 ID 寫入或讀取圖片；管理者讀取他人圖片；檢查兩人的資料庫欄位。
- 預期：沒有接受他人 ID 的寫入端點；一般使用者讀他人回 403；管理者讀取回 200；任何失敗操作不得變更他人欄位。
- 後置狀態：非本人圖片不變。
- 自動化對應：`UserApiTests.已驗證Viewer可上傳覆寫本人圖片且他人不可讀寫`。

### TC-ERR-AVATAR-007 無效格式、損壞或過大檔案

- 對應需求：§1-3、§3.1-3；優先級：P0。
- 前置條件：本人已有正常圖片；準備 GIF、假副檔名、宣告 MIME 與實際內容不符、損壞 PNG、空檔、超出大小上限的檔案。
- 步驟：逐一上傳並讀回原圖片。
- 預期：格式不符回 415；損壞回 400；空檔或過大回 413；內容不被存入，舊圖位元組與稽核成功筆數不變。
- 後置狀態：本人舊圖不變。
- 自動化對應：`AvatarImageProcessorTests.檔名或宣告格式與實際圖片不符應拒絕`、`AvatarImageProcessorTests.損壞圖片應拒絕`、`AvatarImageProcessorTests.空檔或超出上傳限制應拒絕`、`UserApiTests.無效圖片不得覆寫原有大頭貼`。

## 狀態轉換案例

### TC-ST-AVATAR-008 取消、失敗與成功的狀態轉換

- 對應需求：§1-3、§1-4、§4；優先級：P1。
- 前置條件：本人已有圖片，網路可模擬失敗。
- 步驟：選圖後取消；再次選圖確認但使 API 失敗；最後成功上傳新圖。
- 預期：取消及失敗都保留舊圖且顯示可理解訊息；只有成功時刷新圖片，更新後重新整理仍是新圖。
- 後置狀態：資料庫只保存最後成功圖片。
- 自動化對應：`settingsView.spec.ts.上傳失敗時顯示錯誤且不刷新既有圖片`、`settingsView.spec.ts.已驗證Viewer可上傳並刷新大頭貼版本`、`UserApiTests.無效圖片不得覆寫原有大頭貼`。
