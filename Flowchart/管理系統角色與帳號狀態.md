# 管理系統角色與帳號狀態

> 實作同步：2026-09-24。User List 與 User Detail 都使用 `PUT /api/v1/users/{id}/administration`；分離的 role／status endpoints 為相容契約保留。

```mermaid
flowchart TB
    userList([User List]) --> searchUsers[依帳號、姓名、Email 或角色搜尋]
    searchUsers --> hasUsers{找到使用者？}
    hasUsers -->|否| showEmpty[顯示查無使用者]
    showEmpty --> searchUsers
    hasUsers -->|是| excludeBootstrap[清單不回傳 Bootstrap Admin]
    excludeBootstrap --> chooseEntry{選擇操作入口}
    chooseEntry -->|清單| inlineEdit[直接變更系統角色下拉選單或帳號狀態開關]
    chooseEntry -->|詳情| openDetail[開啟 User Detail]
    openDetail --> detailEdit[修改角色與啟用狀態後按儲存]
    inlineEdit --> authorizeAdmin{後端確認具有角色與狀態管理 Functions？}
    detailEdit --> authorizeAdmin
    authorizeAdmin -->|否| forbiddenUser[拒絕操作並顯示權限不足]
    authorizeAdmin -->|是| bootstrapTarget{目標為 Bootstrap Admin？}
    bootstrapTarget -->|是| rejectBootstrap[拒絕異動]
    bootstrapTarget -->|否| emailRule{未驗證帳號要提升為非 Viewer？}
    emailRule -->|是| rejectEmail[回 422 email_not_confirmed]
    emailRule -->|否| lastAdmin{會停用或移除最後一位有效 Admin？}
    lastAdmin -->|是| rejectLastAdmin[拒絕異動]
    lastAdmin -->|否| updateUser[以 Serializable transaction 原子更新角色與啟用狀態]
    updateUser --> updateSucceeded{更新成功？}
    updateSucceeded -->|否| retainUserInput[保留畫面並顯示錯誤]
    updateSucceeded -->|是| invalidateSessions[TokenVersion 加一並撤銷 Refresh Tokens]
    invalidateSessions --> writeUserAudit[(記錄操作者、時間與異動前後內容)]
    writeUserAudit --> userList
```

`/users` 目前直接呼叫 `PUT /api/v1/users/{id}/administration`；角色下拉選單或狀態開關一變更就送出原子請求。`/users/{id}` 保留同一端點的完整表單。Bootstrap Admin 不出現在一般使用者清單，也不能經直接 API 被異動。
