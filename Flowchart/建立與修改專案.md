# 建立與修改專案

> 實作同步：2026-09-24。建立、詳情、修改與軟刪除均由 `ProjectsController` 提供；Code 由後端產生，表單不接受 Code。

```mermaid
flowchart TB
    projectList([Project List]) --> projectAction{選擇操作}
    projectAction -->|新增| newProject[開啟空白專案表單]
    projectAction -->|修改| selectProject[選擇可管理的專案]
    projectAction -->|刪除| selectDeleteProject[選擇專案並讀取最新 rowVersion]
    selectProject --> editProject[載入目前資料與版本]
    newProject --> projectForm[編輯名稱、描述、Owner 與 IANA TimeZoneId]
    editProject --> projectForm
    projectForm --> submitProject{選擇動作}
    submitProject -->|取消| projectList
    submitProject -->|儲存| authorizeProject{後端授權通過？}
    authorizeProject -->|否| forbiddenProject[顯示權限不足]
    authorizeProject -->|是| projectValid{欄位、IANA 時區與 Administrator Owner 均有效？}
    projectValid -->|否| showProjectValidation[顯示欄位錯誤]
    showProjectValidation --> projectForm
    projectValid -->|是| versionConflict{修改時發生版本衝突？}
    versionConflict -->|是| showProjectConflict[顯示資料已更新並要求重新載入]
    versionConflict -->|否| ensureOwnerManager[確保 Owner 是成員且具有 ProjectManager]
    ensureOwnerManager --> saveProject[建立或更新專案]
    saveProject --> saveProjectSucceeded{儲存成功？}
    saveProjectSucceeded -->|否| retainProjectInput[保留輸入並顯示錯誤]
    saveProjectSucceeded -->|是| projectDetail([顯示成功訊息並進入專案詳情])
    selectDeleteProject --> authorizeDelete{Administrator 或 Admin？}
    authorizeDelete -->|否| forbiddenProject
    authorizeDelete -->|是| confirmDelete{確認軟刪除？}
    confirmDelete -->|否| projectDetail
    confirmDelete -->|是| deleteConflict{rowVersion 過期？}
    deleteConflict -->|是| showProjectConflict
    deleteConflict -->|否| softDeleteProject[寫入 DeletedAt、DeletedByAccountId 與 AuditLog]
    softDeleteProject --> projectList
```

Project 名稱儲存前 trim 後必須為 1–200 個字元；Description 為選填，若有值則 trim 後最多 4000 個字元。Owner 必須是已啟用、Email 已驗證且系統角色恰為 `Administrator` 的帳號；`Admin`、`User`、`Viewer` 均不得擔任。建立時 Owner 會自動成為成員並取得 `ProjectManager`；修改專案時，新 Owner 還必須已是該專案成員，缺少 `ProjectManager` 時由同一交易補上。舊 Owner 原有的 Project Roles 不會自動移除。

每個 Project 必須明確指定合法的 IANA `TimeZoneId`，不得為空白、Windows timezone ID 或未知值，也不得在新增時自動套用系統預設。既有 Project 的時區由部署設定透過 migration 回填；設定缺少或無效時 migration 必須 fail-fast。

Project 軟刪除只開放給 `Administrator` 與 `Admin`，且必須帶最新 rowVersion。成功後 Project 與所屬資料從一般 scope 隱藏，但成員、Task、Comment 與 history 不實體刪除；本期無 restore 或 permanent-delete 入口。
